# DriveBook Operational Engine

DriveBook is a high-concurrency backend service designed to handle dispatching, time-slot scheduling, and fleet distribution under strict latency SLAs.

## Key Technical Challenges

- **Race Condition Prevention**: Multiple dispatch requests targeting overlapping slots required distributed locking via Redis `SETNX` with self-expiring leases and Lua unlock scripts.
- **Database Index Optimization**: Geospatial range queries using PostgreSQL composite indexing and bounding box filtering to maintain sub-15ms response times during peak demand.
- **Worker Pool Architecture**: Utilizing Go channels and bounded worker pools to process batch routing updates without unbounded memory growth under sudden spikes.

```go
// Worker pool snippet handling async distribution updates
func (d *Dispatcher) ProcessBatches(ctx context.Context, jobs <-chan Job) {
    for {
        select {
        case <-ctx.Done():
            return
        case job, ok := <-jobs:
            if !ok {
                return
            }
            d.assignOptimalRoute(ctx, job)
        }
    }
}
```

## Results & Benchmarks

- Handled 1,200 requests/second with p99 latency under 24ms.
- Zero double-booking errors across stress test runs simulating 10,000 concurrent driver check-ins.
